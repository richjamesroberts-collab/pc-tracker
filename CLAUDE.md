# CLAUDE.md

Guidance for Claude Code when working in this repository.

## Project Overview

D&D 5e (2014) **player** tracker: a phone-first web app each player uses at the table for their own character. Sister project to `../5e-combat-tracker` (the DM's tool) but fully standalone: no sync, no backend, each phone keeps its own data.

Tracks: name, portrait, XP (next-level progress and level up with hit points, or milestone levelling), base ability scores (racial increases, Primal Champion and attuned magic items applied on top), AC (worked out from worn armor, DEX, Unarmored Defense and item bonuses, or entered), HP (current/max, raised by items that change CON), temp HP, death saves, hit dice (spent on a short rest, half back on a long rest), proficiency bonus, spell slots (incl. warlock pact slots and Mystic Arcanum), sorcery points with Font of Magic and metamagic, known/prepared spells, concentration, race/subrace, skills (proficiency, expertise, racial skills, Jack of All Trades, item bonuses), saving throws, weapon proficiencies, fighting styles, senses (darkvision etc. from race and class, plus the player's own), damage resistances and immunities (race, class/subclass features, attuned items), attacks with equipped weapons, limited-use class/subclass/racial feature counters (`RESOURCES` in `rules/features.ts`, including per-rune counters owned by a class option, and ones that don't come back on a rest like Divine Intervention, which a long rest keeps) (plus custom counters that recharge on a short or long rest, or never), feature text, feats and class options (invocations, maneuvers, infusions and the like), a step-by-step level up, and an inventory: coins (with change-making when spending), magic items (attunement, charges with dawn recharge) and mundane gear (equipment packs unpack into their contents), plus custom items and carried weight.

## Tech Stack

- Svelte 5 (runes) + SvelteKit, `adapter-static` with **hash routing** (`router.type: 'hash'`), so the build is a single `index.html` that works on any static host. Hash routing ignores `+page.ts`/`+layout.ts` page options; don't add them. For a subfolder host set `BASE_PATH` at build time (the GitHub Pages workflow does this).
- TypeScript, Dexie.js over IndexedDB (`pc-tracker` database, `characters` table)
- Vitest for rules and backup tests
- Service worker (`src/service-worker.ts`) caches the app for offline use; web manifest + icons in `static/`
- Theme tokens in `src/app.css` are shared with the combat tracker; all colours come from tokens

## Game data

`npm run data` (alias `npm run spells`) regenerates the bundled JSON in `src/lib/data/` from a local 5etools checkout (`../5etools-2014-src`, override with `FIVETOOLS_DIR`): `spells.json` (all PHB/XGE/TCE spells), `classes.json` (class and subclass features, keyed by our class and subclass keys), `races.json` (PHB, Volo's Guide (VGM) and Monsters of the Multiverse (MPMM) races, and Custom Lineage), `items.json` (DMG/XGE/TCE magic items, plus generic variants like +1 Weapon and Flame Tongue), `gear.json` (PHB weapons, armor, tools, adventuring gear and packs; DMG poisons, gems and art objects; bundles like Arrows (20) fold into a default quantity on the single item), `feats.json` (PHB/XGE/TCE feats, with the ability increases, saving throw, skill and expertise choices and Tough's HP that level up applies), `options.json` (invocations, pact boons, maneuvers, arcane shots, runes, infusions and elemental disciplines, with level and pact prerequisites) `race-abilities.json` (racial ability score increases, darkvision and resistances/immunities, bundled with the app shell) and `spell-grants.json` (spells a class, subclass, class option (`option:<ref>`: pact boons, invocations, disciplines), fighting style (`style:<key>`), feat (`feat:<ref>`), race (`race:<key>`) or subrace (`subrace:<race>/<sub>`) gives, from 5etools `additionalSpells` plus hand-added Primal Awareness, Spell Mastery and Signature Spells and the `CAST_OVERRIDES` table, bundled with the app shell: `prepared` grants are always prepared (domain, oath, circle, specialist spells), `known` grants are known on top of the class count (Aberrant Mind's psionic spells, ranger subclass magic), `innate` grants are cast only their own ways (invocations, ki spells, racial spells, feats; with slots too when `slots`), `expanded` grants add to the list the class picks from (warlock patrons, Divine Soul's cleric list); grants can have fixed spells, `choices` (pick N matching a filter: Magical Secrets, Magic Initiate), a `variant` the player picks (Land terrain, Divine Soul affinity, a feat's class), a `swap` rule (Aberrant Mind, Clockwork Soul) and `cast` ways besides a slot (at will, N per rest, ki/sorcery/psionic points, a pact slot once a day, ritual only). Everything is `free` (doesn't count against limits) except expanded lists and Bard Magical Secrets). Everything is `free` (doesn't count against limits) except expanded lists and Bard Magical Secrets). MPMM reprints every VGM race: the MPMM version has the plain key (`tabaxi`) and the VGM one a `-vgm` suffix (`tabaxi-vgm`). MPMM races have no fixed increases; their choice allows the same ability up to twice (`choose.max`), so `raceAbilityChoices` can repeat an ability (`['dex', 'dex', 'cha']` = +2 DEX, +1 CHA). Magic items carry `effects` (ability scores set or raised, AC, spell attack/DC, weapon attack/damage, damage resistances/immunities and condition immunities; potions excluded) and armor carries `armor` (type and base AC). Weapons (gear, and magic weapons of a set kind) carry `weapon` (base PHB weapon, category, damage, properties, range); generic magic weapons (+1 Weapon) get one when the player picks the base weapon in the item sheet. Subclasses are PHB/XGE/TCE plus three older ones that already had keys: Cleric Arcana (SCAG), Paladin Oathbreaker (DMG), Warlock Undead (VRGR). The script fails if counts drop or a PHB/XGE/TCE subclass has no key in its `SUBCLASS_KEYS` table. The output is committed and shipped publicly, by the owner's choice.

Spell packs (`.spellpack.json`, stored in the `spellPacks` table) are for extra spells players import on their own phone. Characters keep a `spellCache` copy of pack spells they use, so backups restore on phones without the pack. Lookup order: installed library (bundled spells, overridden by packs with the same id) → custom spells → cache.

## Architecture

- `src/lib/rules/` — pure 5e rules (slot tables, HP/temp/death saves, sorcery points, rests and hit dice, item attunement/charges/dawn, coins).
- `src/lib/rules/stats.ts` — worked-out numbers. The player enters base values (`abilities`, `hpBase`, `acAuto`/`acBase`/`acAdjust`, optional `initiativeOverride`/`spellModOverride`); `recompute` sets `ac`, `hpMax`, `spellMod` and `initiativeModifier` from them and runs after every `session.mutate`/`record`, on load and on import. Never set those four directly. Item effects are copied onto inventory entries so this stays synchronous; entries from before effects existed are filled in from the bundled data by the character layout (`fillItemDetails`), keeping the AC and max HP shown unchanged. Fields added to bundled items later (weapon stats) are filled once per `ITEM_DATA_VERSION` by `fillItemData`; bump it and extend that function when items gain new copied fields. Mutate a `Character` draft in place. Tested in `rules.test.ts`.
- `src/lib/rules/attacks.ts` — attacks with equipped weapons plus an unarmed strike (ability choice incl. finesse, Martial Arts, Hex Warrior, Battle Ready; proficiency; magic bonuses; fighting styles), Extra Attack counts, and table notes (Sneak Attack, Rage, smites, critical range, off-hand). Worked out in the view, not stored; every part carries a `from` saying where it comes from (ability score origin, proficiency source, item, fighting style), shown in the attack sheet. `skills.ts` works out skill modifiers the same way (`skillProficiencies`/`skillExpertise` picks plus fixed racial skills in `RACE_SKILLS`, Jack of All Trades, Remarkable Athlete, item bonuses and advantage notes by item `ref`, armor Stealth disadvantage); `saves.ts` does saving throws (class saves, `saveProficiencies` picks, Diamond Soul, Slippery Mind, Aura of Protection, item bonuses, racial and class advantage notes). Both open in `CheckSheet`. `spellcasting` in `stats.ts` explains the spellcasting modifier, save DC and attack bonus (`SpellcastingSheet`, opened from the Spellcasting tiles on Vitals). `proficiency.ts` (class/subclass/race weapon proficiencies plus `weaponProficiencies`), `senses.ts` (race darkvision from `race-abilities.json`, class senses, plus `senses`), `defenses.ts` (resistances and immunities from race data, a `FEATURES` table of class/subclass features, items in use, plus the player's own `defenses`; shown on Vitals under AC/HP), `xp.ts` (XP table, hit points per level, `levelUp`), `levelup.ts` (what each new level asks for: subclass, Ability Score Improvement or feat, a Variant Human or Custom Lineage feat at 1st level, fighting styles, weapon picks (Hobgoblin, Bladesinger, Kensei), expertise, metamagic, class option counts, new cantrips and spells; `levelUpNeeds(prev, next, first)` counts a new character's 1st level from nothing; `levelUpChanges` lists what goes up; `applyChoices` applies a level's choices and `applyLevelUp` adds the level and its HP, including HP from a higher CON or Tough on earlier levels; `startingHp` for a character built level by level). The Defense fighting style is applied in `stats.ts` AC.
- `src/lib/rules/grants.ts` — granted spells. Fixed ones are worked out from class, subclass, level, `classOptions`, `fightingStyles` and `grantVariants`, never stored; picks for a grant's choices are `Character.spells` entries with `grant` (the choice key), and a spell swapped into a subclass list also has `replaces` (the fixed spell it stands for). `characterSpells` merges them in with their `grant` (tag like Psionic or Domain); free ones never count against cantrips known, spells known or prepared (a spell the player also picked by hand shows once, as granted). In the spellbook each grant list has a filter where choices are filled and variants picked (for characters from before choices existed); expanded spells join the class list. Level up has a Granted spells step for variants, new choices (Magical Secrets come out of the new spells count) and one swap; the spells step offers expanded spells and counts Eldritch Knight / Arcane Trickster off-school picks (`schoolLimit`). An Arcane Trickster's Mage Hand is a grant, not +1 on `cantripsKnown`. Granted spells' own ways to cast show in `CastSheet` (`grantCastOptions`/`spendCast`): free casts are counted in `resourcesUsed` under `cast:<grant>:<spell>` (or `cast:<pool>`), except racial spells, which spend the race's counter of the same name in `features.ts`; short-rest ones come back in `shortRestCasts`. Innate spells offer no slots unless `slotsAllowed`. Non-casters with granted spells (Shadow monk, tiefling fighter) get the Spells tab. A grant's `ability` (fixed, the feat's raised ability, or the best of a MPMM race's choices) gives its spells their own attack and DC (`grantCasting`), shown in `CastSheet` with `spellNotes` (`rules/spellnotes.ts`: Eldritch Blast beams and invocations, Potent Spellcasting, Empowered Evocation, Elemental Affinity and other features that change a spell, worked out from its text and lists).
- `src/lib/session.svelte.ts` — the open character. All changes go through `session.mutate(label, fn)`, which copies, applies, saves to IndexedDB and offers Undo via the toast. `session.record` saves bookkeeping without an undo step.
- `src/lib/library.svelte.ts` — spell library (bundled spells + installed packs), spell lookup for a character, spell copies.
- `src/lib/data/` — `classes.ts` (class/subclass keys, saves), `races.ts` (race/subrace keys grouped by book, dragon ancestry, `raceLabel`), `content.ts` (`loadContent`, `loadItems` and `loadGear` lazy-load the generated JSON; `featureGroups`; `inventoryItem`, `gearInventoryItem`, `unpack`), plus the generated `spells.json`, `classes.json`, `races.json`, `items.json`, `gear.json`.
- Inventory items (`kind: 'magic' | 'gear'`) copy name, type, rarity, attunement, weight and charges from the bundled item when added (so restore links and lists work without loading the JSON); only the description and stats are looked up by `ref` in `items.json` or `gear.json`.
- `src/lib/backup/` — backup file format (`{ app, schemaVersion, character }`), validation/migration in `readBackup`, restore links (`?restore=<deflate+base64url>`, no portrait or spell copies), spell pack files (`packs.ts`), share-sheet saving, and back-up reminders (`reminder.svelte.ts`: Vitals reminds when the player comes back, after 15+ minutes away or a fresh open, to a character left with changes not backed up; browsers can't prompt as the app closes).
- Routes: `/` list, `/new`, `/import` (backups and spell packs), `/packs`, `/c/[id]` (Vitals: AC, HP, saves, attacks, spellcasting, spell slots, sorcery points, limited-use counters (`CountersCard`) and the rest buttons), `/c/[id]/stats` (ability scores, proficiency, hit dice, saves, skills, experience), `/c/[id]/spells`, `/c/[id]/book`, `/c/[id]/features`, `/c/[id]/inventory`, `/c/[id]/edit`, `/c/[id]/level-up` (steps through a level: what's new, subclass, ASI or feat, hit points, fighting style, weapons, expertise, metamagic, class options, spells, review; one `session.mutate` at the end, opened from the Experience sheet). The steps live in `LevelUpFlow` (`mode: 'level-up' | 'create'`); `/new` uses it too, as a sequence of screens: the basics (name, race and subrace, class, level, and an optional photo), ability scores, skills (`CharacterForm` `sections`; the class and race skill lists from `skillChoices` are marked on the chips), each level from 1 to the starting level that asks for something, the optional details (XP, AC, speed, senses and the rest, shown on the levelled-up character), then max HP. The new-character form never shows subclass, max HP, extra saving throw picks, weapon proficiencies, fighting styles, feats, class options or metamagic; the level steps ask for those. Each level's `FlowPicks` are kept, so going back keeps them until an earlier level's choices, or the class, race, level, scores or skills, change. The bottom nav has one Spells tab for both `/spells` and `/book`; `SpellNav` switches between them. Saving throws (`SavingThrows`) show on both Vitals and Stats.

When the `Character` shape changes, give new fields defaults in `readBackup` (and a Dexie upgrade) so old backups still import. Bump `SCHEMA_VERSION` only for changes older apps can't read.

## Deploy

`.github/workflows/deploy.yml` tests, builds and publishes to GitHub Pages on every push to `main`.

## Commands

```bash
npm run data         # Regenerate bundled game data from 5etools (alias: npm run spells)
npm run dev          # Dev server on localhost
npm run dev:phone    # Dev server on the LAN, open http://<laptop-ip>:5173 on a phone
npm run build        # Static site in build/
npm run preview      # Serve the build on the LAN
npm run check        # svelte-check
npm test             # Vitest
```
